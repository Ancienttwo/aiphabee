版本：v0.1
目标：先上线 **CF Worker Generic 问答 Agent**，再上线 **付费独立 AI 投研助手 FastClaw Runner**。
核心原则：**前端只连接 AiphaBee API；AiphaBee API 是唯一 authority；FastClaw 只做 paid research runner / execution plane。**

---

## 1. 产品一句话

AiphaBee 提供两层 Agent：

**Layer 1：Generic 问答 Agent**
面向所有用户的轻量问答、解释、产品导航、公开信息分析能力，部署在 Cloudflare Worker，基于 Vercel AI SDK v7。

**Layer 2：付费 AI 投研助手**
面向付费用户的专属深度投研 Agent，由 AiphaBee API 鉴权、控权、审计、计费，FastClaw 作为独立 Runner 执行长任务、工具循环、记忆、sandbox 和深度报告。

FastClaw 的定位不是“新 API”，也不是“用户直接访问的投顾后台”，而是 AiphaBee control plane 后面的 **research execution plane**。FastClaw 官方定位是 Agent Factory，负责 agent personality、memory、skills、tools、LLM 通信、tool execution、sandbox isolation 和 session management，这个能力适合承接付费深度投研 Runner。([GitHub][1])

---

## 2. 背景与问题

AiphaBee 的 Agent 需求天然分裂成两类。

第一类是高频、轻量、低成本的通用问答。用户会问“这个指标是什么意思”“这条新闻怎么看”“我应该怎么使用某个功能”“帮我总结这个页面”。这类问题需要低延迟、稳定、便宜，并且不需要重型 agent memory 或 sandbox。

第二类是低频、高价值、长链路的深度投研。用户会问“帮我分析我的 NVDA 仓位风险”“过去三次 earnings 后股价和估值怎么变”“结合我的 watchlist 生成本周风险报告”。这类任务需要更强的工具编排、文件/报告处理、长期记忆、session 隔离、可能的 sandbox 和更长运行时间。

把两类能力都塞进 Worker 会让 Worker 变成重型 agent runtime；把所有 Agent 都拆成独立服务又会导致鉴权、计费、审计、证据链、合规边界分裂。因此本 PRD 采用双层架构：**轻任务在 Worker 内解决，重任务交给 FastClaw Runner，但所有 authority 留在 AiphaBee API。**

---

## 3. 产品目标

### 3.1 P0 目标

上线一个稳定的 Generic 问答 Agent，支持 streaming、基础工具调用、证据引用、错误降级和使用量计量。

上线一个付费 AI 投研助手 Alpha，前端仍只连接 AiphaBee API；AiphaBee API 调 FastClaw `/v1/chat/completions`，并通过 `user` / `X-Fastclaw-End-User` / deterministic session key 做用户与会话隔离。FastClaw 的 upstream 文档明确建议上游 SaaS 后端持有 API key，并把自己的 auth/session 映射到 FastClaw user 或 `X-Fastclaw-End-User`；API key 不应暴露给浏览器或移动端。([GitHub][2])

实现付费 entitlement：只有付费用户可进入 Layer 2；免费用户只能使用 Layer 1，并在合适场景看到升级入口。

实现 runner 隔离：FastClaw 挂掉时，AiphaBee API 仍可登录、加载主页面、使用 Generic Agent，并把 premium run 标记为 `runner_unavailable` / `retryable`，而不是拖垮主 API。

实现基础投研合规边界：MVP 对外叫 **AI 投研助手**，不叫 **AI 投顾**；默认模式是 `research_only`，不提供个性化买入/卖出/持有建议、目标价、止损价、仓位比例或自动交易。

### 3.2 非目标

MVP 不做自动交易。

MVP 不让前端直连 FastClaw。

MVP 不让 FastClaw 直接写 AiphaBee production DB。

MVP 不把 FastClaw usage 作为 AiphaBee billing 的唯一事实源；FastClaw usage 只能作为 runner raw meter，AiphaBee billing 才是 source of truth。

MVP 不承诺“注册投顾”“保证收益”“个性化投资建议”。美国 SEC 对 investment adviser 的定义涉及“为了报酬、作为业务，向他人提供证券建议或证券报告/分析”；这意味着付费个性化证券建议会触发更高合规风险。([SEC][3])

## 4. 用户与场景

### 4.1 用户类型

**免费用户 / 新用户**
主要使用 Generic Agent，问产品使用、市场概念、公开信息解释。目标是提高激活和留存，并引导高价值用户升级。

**普通付费用户**
使用专属 AI 投研助手做 watchlist 分析、组合风险解释、新闻影响总结、财报问答、投资研究报告。

**高阶付费用户**
需要更深的多步骤研究：多公司对比、earnings transcript 分析、历史事件复盘、仓位集中度/相关性/行业暴露分析。

**运营 / 合规 / 支持人员**
需要查看 run 日志、用户反馈、blocked response、证据链、runner health、使用成本和异常请求。

## 5. 产品分层

| Layer   | 名称               | 入口                         | 适用用户    | 执行位置                   | 核心价值                |
| ------- | ---------------- | -------------------------- | ------- | ---------------------- | ------------------- |
| Layer 1 | Generic 问答 Agent | 全站 Ask / 页面内问答             | 免费 + 付费 | Cloudflare Worker      | 快速、便宜、稳定、低风险        |
| Layer 2 | AI 投研助手          | Premium Research Assistant | 付费用户    | FastClaw Runner，API 代理 | 深度研究、长期记忆、工具循环、报告生成 |

Layer 1 是默认能力。Layer 2 是付费能力。用户不需要理解底层分层，但 UI 要明确区分“快速问答”和“深度投研”。

## 6. Layer 1：CF Worker Generic 问答 Agent

### 6.1 定位

Generic Agent 是 AiphaBee 的基础问答层。它回答低风险、轻量、即时的问题，不承担长任务，不做个人化投研结论，不做交易建议。

适合问题：

```text
这个财务指标是什么意思？
这条新闻主要影响哪些行业？
帮我解释一下 PE / EV/EBITDA / free cash flow。
这个页面的 evidence 是什么意思？
AiphaBee 的 portfolio risk view 怎么用？
```

不适合问题：

```text
我现在应该买 NVDA 吗？
帮我设置止损价。
根据我的资产给我仓位比例。
今天卖掉哪只股票？
```

这些问题应进入合规 soft-block，或者在付费用户场景下转到 Layer 2 的 `research_only` 分析，但仍不能直接给出交易指令。

### 6.2 技术基线

Layer 1 使用 Vercel AI SDK v7 的 `streamText` / tool calling / multi-step tool loop。AI SDK 文档说明 `streamText` 与 `generateText` 支持通过 `stopWhen` 做多步 tool call：模型生成 tool call 后执行工具，再把结果带回模型继续生成，直到满足停止条件。([AI SDK][4])

Cloudflare 官方文档也说明 Workers AI 可以与 Vercel AI SDK 一起使用，并展示了 `generateText` 与 `streamText` 的 Worker 示例；因此 Layer 1 在 Cloudflare Worker 上实现是合理方向。([Cloudflare Docs][5])

但需要注意 AI SDK v7 的运行时要求：Vercel 文档写明 AI SDK 7 要求 Node.js 22+ 和 ESM imports。Cloudflare Worker 不是标准 Node runtime，所以 P0 必须做一个 compatibility spike，确认当前 Worker bundle、`nodejs_compat`、AI Gateway provider / Workers AI provider 的组合能稳定跑通。([Vercel][6])

### 6.3 Layer 1 功能需求

**P0：基础聊天**

用户可在全站 Ask 输入问题。

系统返回 streaming answer。

回答必须带 `answer_type`：

```text
general_education
product_help
public_market_research
account_help
blocked_or_redirected
```

当问题涉及具体证券时，默认加上“研究信息，不构成投资建议”的轻提示。

**P0：工具调用**

Generic Agent 允许调用轻量工具：

```text
search_public_knowledge
get_company_profile
get_public_market_snapshot
get_news_summary
get_filing_summary
get_product_help_doc
get_user_visible_page_context
```

Generic Agent 不允许调用：

```text
broker_trade
portfolio_write
payment_write
user_secret_read
fastclaw_admin
personal_recommendation_engine
```

**P0：证据链**

所有事实性市场回答必须带 evidence items。每个 evidence item 至少包含：

```json
{
  "evidence_id": "ev_...",
  "source_type": "filing|news|market_data|internal_doc",
  "source_title": "...",
  "source_url_or_ref": "...",
  "retrieved_at": "...",
  "quote_or_summary": "...",
  "confidence": 0.0
}
```

**P0：限流与预算**

免费用户每日 N 次 Generic Agent。

付费用户每日更高额度。

单次 Generic run 有 token budget、tool budget、wall-clock timeout。

**P0：错误降级**

模型超时：返回“当前 AI 服务繁忙，可重试”，不影响主 API。

工具超时：继续生成，但明确标记“部分数据暂不可用”。

合规 block：解释不能回答的原因，并提供安全替代表达，例如“我可以帮你比较风险因素和财务指标，但不能告诉你现在是否应该买入”。

### 6.4 Layer 1 成功指标

首 token p95 < 2 秒。

完整回答 p95 < 20 秒。

Generic Agent 请求失败率 < 1.5%。

工具调用失败率 < 5%。

免费到付费转化相关 CTA 点击率 > 3%。

被用户标记“有帮助”的回答比例 > 60%。

## 7. Layer 2：付费 AI 投研助手 FastClaw Runner

### 7.1 定位

Layer 2 是付费用户的专属深度投研助手。它不是简单聊天，而是一个带记忆、工具、session、报告能力的 research agent。

适合问题：

```text
帮我分析我的 NVDA 仓位主要风险。
结合我的 watchlist，生成本周风险摘要。
比较 AMD、NVDA、AVGO 最近一个季度的增长质量。
这家公司 earnings call 里有哪些管理层态度变化？
基于我的组合，哪些行业/因子暴露过高？
```

仍不直接回答：

```text
你建议我今天买哪只？
给我一个买入价和止损价。
我应该把 30% 仓位换成某个 ETF 吗？
帮我自动调仓。
```

这些请求应被改写成研究输出：

```text
我不能替你作出个性化买卖决策。
我可以列出影响决策的关键因素、风险、估值区间、情景分析和你需要确认的问题。
```

### 7.2 FastClaw 集成方式

AiphaBee API 调用 FastClaw 的 upstream `/v1/chat/completions`。FastClaw 文档说明该接口是 OpenAI-compatible endpoint，并支持 `agent_id`、`user`、`params`、attachments、streaming SSE 等扩展；`params` 可作为 per-turn structured context。([GitHub][2])

推荐内部请求：

```http
POST /v1/chat/completions
Authorization: Bearer <server_side_agent_scoped_fcak>
X-Fastclaw-End-User: <aiphabee_user_id>
X-Fastclaw-Session-Key: research:<user_id>:<conversation_id>
Content-Type: application/json
```

```json
{
  "agent_id": "agt_research_template_or_user_clone",
  "stream": true,
  "user": "aiphabee_user_123",
  "messages": [
    {
      "role": "user",
      "content": "帮我分析我的 NVDA 仓位风险"
    }
  ],
  "params": {
    "run_id": "run_...",
    "tenant_id": "tenant_...",
    "jurisdiction": "US",
    "mode": "research_only",
    "risk_profile_ref": "rp_...",
    "portfolio_snapshot_ref": "ps_...",
    "market_data_snapshot_ref": "md_...",
    "allowed_tools": [
      "market_snapshot",
      "portfolio_readonly",
      "filing_search",
      "news_search",
      "factor_exposure"
    ],
    "forbidden_outputs": [
      "personalized_buy_sell_hold",
      "target_position_size",
      "trade_execution"
    ]
  }
}
```

### 7.3 Provisioning 模式

**MVP Alpha：shared advisor template + app-user 隔离**

一个 FastClaw advisor template agent。

每个 AiphaBee user 映射成 FastClaw app-user。

用 deterministic session key 做会话隔离。

优点是上线快、成本低。缺点是 agent identity 不是每个用户独立，主要靠 app-user/session/memory 隔离。

**Premium v1：每个付费用户 clone 一个专属 agent**

付费成功后，AiphaBee 调 operator/admin flow 创建或 clone 一个用户专属 research agent。

每个用户有自己的 agent config、memory、SOUL、tool policy、risk mode。

适合“独立 AI 投研助手”的产品承诺。

**Enterprise / 高敏版本：独立 namespace 或独立 FastClaw instance**

当接入真实券商账户、机构客户、敏感交易数据时，考虑每个机构独立 FastClaw instance 或至少独立 DB namespace、secrets、audit trail。

### 7.4 Layer 2 功能需求

**P0：付费校验**

用户进入 AI 投研助手前，AiphaBee API 校验：

```text
session valid
subscription active
jurisdiction allowed
risk disclosure accepted
monthly usage quota not exceeded
```

校验失败不调用 FastClaw。

**P0：投研 onboarding**

首次使用时收集：

```text
投资经验：beginner / intermediate / advanced
目标：education / research / portfolio_risk / trading_support_not_enabled
风险偏好：low / medium / high
市场：US / HK / CN / crypto-disabled-by-default
是否接受 research_only disclaimer
```

MVP 不需要完整 KYC，但需要 risk disclosure acknowledgement。

**P0：深度研究 run**

用户发起问题后，API 创建 `agent_run`，状态为 `queued`。

API 校验 entitlement、预算、工具 allowlist。

API 调 FastClaw。

API 接收 FastClaw streaming delta，并转换成 AiphaBee 统一 SSE event。

API 对最终回答做 compliance/evidence validation。

通过后返回 final answer；不通过则 soft-block、rewrite 或标记人工审核。

**P0：工具网关**

FastClaw 不直接连 AiphaBee DB。FastClaw 工具只能调用 AiphaBee Tool Gateway。

Tool Gateway 要求 job-scoped token：

```json
{
  "run_id": "run_...",
  "user_id": "u_...",
  "scopes": [
    "portfolio:read",
    "market_data:read",
    "filings:read"
  ],
  "exp": 1760000000,
  "max_calls": 30,
  "max_cost_usd": 1.0
}
```

Tool Gateway 返回结构化结果和 evidence metadata。

**P0：报告输出**

Layer 2 最终回答默认包含：

```text
结论摘要
关键证据
风险因素
反向观点
需要用户确认的问题
数据时间戳
免责声明
```

对于长任务，允许生成 report artifact，但先保存在 AiphaBee 侧，而不是只存在 FastClaw workspace。

**P1：长期记忆**

记录用户偏好：

```text
关注行业
常看股票
风险偏好
回答风格
常用比较维度
```

不记录敏感原始凭证。

所有 memory 写入必须经过 AiphaBee API policy，可设置用户可查看、可删除。

**P1：研究任务队列**

复杂任务可以异步执行：

```text
run.created
run.queued
runner.started
tool.started
tool.finished
draft.generated
validator.started
answer.final
```

用户离开页面后仍可回到历史 run 查看结果。

**P2：主动提醒**

基于用户 watchlist / portfolio 生成：

```text
earnings reminder
risk alert
news impact digest
weekly portfolio risk summary
```

P2 之前不做主动个性化买卖建议。

## 8. 统一前端体验

前端只接 AiphaBee API，不知道 FastClaw 存在。

推荐一个统一入口：

```text
Ask
  ├─ 快速问答
  └─ 深度投研助手 Pro
```

免费用户看到“深度投研助手 Pro”时，允许点击预览，但提交时触发升级页。

付费用户在问题框旁看到模式选择：

```text
快速回答
深度研究
生成报告
```

系统可以自动路由，但必须显示状态：

```text
正在使用快速问答
正在调用你的 AI 投研助手
正在检索财报
正在分析组合风险
正在生成证据链
```

当 FastClaw 不可用时，前端显示：

```text
你的 AI 投研助手暂时不可用。你仍可以使用快速问答，或稍后重试深度研究。
```

不能显示 provider 错误、FastClaw 内部错误、API key 错误。

## 9. 路由策略

AiphaBee API 做 route decision。

```json
{
  "requested_layer": "auto|generic|research",
  "selected_layer": "generic|research",
  "route_reason": "free_user|premium_user|deep_research_intent|portfolio_context_needed|runner_unavailable|compliance_block",
  "fallback_allowed": true
}
```

路由规则：

| 场景                              | 用户 | 路由                              |
| ------------------------------- | -- | ------------------------------- |
| 产品帮助、概念解释                       | 任意 | Generic                         |
| 公开市场轻分析                         | 任意 | Generic                         |
| 需要 portfolio / watchlist / 用户偏好 | 付费 | Research                        |
| 需要长报告 / 多工具 / 文件分析              | 付费 | Research                        |
| 免费用户请求深度研究                      | 免费 | Generic + 升级 CTA                |
| 请求买卖建议 / 目标仓位 / 自动交易            | 任意 | Compliance rewrite/block        |
| FastClaw down                   | 付费 | Generic fallback 或 queued retry |

## 10. 系统架构

```text
Web / Mobile
    |
    | HTTPS / SSE
    v
AiphaBee API on Cloudflare Worker
    |
    |-- Auth / session / tenant
    |-- Entitlement / subscription
    |-- Route decision
    |-- Compliance policy
    |-- Usage metering
    |-- Evidence validation
    |-- Audit log
    |
    | Layer 1
    |--> Generic Agent Runner
    |      Vercel AI SDK v7
    |      light tools
    |
    | Layer 2
    |--> FastClaw Adapter
           |
           | internal only
           v
        FastClaw Runner
           |
           | job-scoped token
           v
        AiphaBee Tool Gateway
           |
           | read-only
           v
        Market Data / Filings / News / Portfolio Snapshot
```

Cloudflare Worker 对 HTTP-triggered requests 没有硬性 duration limit，只要 client 保持连接就可以继续处理和 streaming；但 client 断开或 response 完成后，请求关联任务可能被取消，`ctx.waitUntil()` 也只是延长有限时间。因此 Generic Agent 可以在 Worker streaming，但付费长任务仍应走持久化 run state + Runner/queue，而不是依赖浏览器连接活着。([Cloudflare Docs][7])

## 11. API 设计

### 11.1 Public API

**创建 Agent Run**

```http
POST /api/agent/runs
```

```json
{
  "message": "帮我分析我的 NVDA 仓位风险",
  "mode": "auto",
  "conversation_id": "conv_...",
  "page_context": {
    "page": "portfolio",
    "symbols": ["NVDA"]
  }
}
```

Response：

```json
{
  "run_id": "run_...",
  "selected_layer": "research",
  "stream_url": "/api/agent/runs/run_.../stream",
  "status": "queued"
}
```

**读取 stream**

```http
GET /api/agent/runs/:run_id/stream
```

SSE event envelope：

```json
{
  "run_id": "run_...",
  "event_index": 12,
  "event_type": "tool.finished",
  "layer": "research",
  "created_at": "2026-07-03T00:00:00Z",
  "payload": {
    "tool_name": "portfolio_readonly",
    "summary": "Loaded 12 positions"
  }
}
```

**历史 run**

```http
GET /api/agent/runs/:run_id
GET /api/agent/conversations/:conversation_id/runs
```

**投研助手 onboarding**

```http
POST /api/research-agent/onboarding
```

```json
{
  "experience": "intermediate",
  "risk_preference": "medium",
  "markets": ["US"],
```

### 11.2 Internal API

**FastClaw Adapter**

```http
POST /internal/runners/fastclaw/chat
```

只允许 Worker/API 调用。该 adapter 负责：

```text
注入 FastClaw API key
设置 X-Fastclaw-End-User
设置 X-Fastclaw-Session-Key
注入 params
转换 FastClaw SSE 为 AiphaBee SSE
处理 timeout / retry / circuit breaker
```

**Tool Gateway**

```http
POST /internal/tools/:tool_name
Authorization: Bearer <job_token>
```

工具网关负责鉴权、限流、审计、脱敏、返回 evidence。

## 13. 合规与安全边界

### 13.1 命名边界

产品对外命名建议：

```text
AI 投研助手
AI Research Assistant
Portfolio Research Copilot
```

暂不建议：

```text
AI 投顾
AI Financial Advisor
自动投资顾问
智能荐股助手
```

中国《证券投资顾问业务暂行规定》对证券投资顾问业务的描述包括：接受客户委托，提供涉及证券及证券相关产品的投资建议服务，辅助客户作出投资决策，并直接或间接获取经济利益；投资建议服务内容包括投资品种选择、投资组合、理财规划建议等。([shanghaiinvest.com][8])

### 13.2 输出边界

MVP 允许：

```text
解释指标
总结财报
比较公司
列风险因素
列情景分析
解释组合暴露
生成研究清单
生成需要用户自行确认的问题
```

MVP 不允许：

```text
明确说“你应该买/卖/持有”
给出个性化目标仓位
给出止损价/买入价/卖出价
承诺收益
代替用户下单
使用未授权个人金融数据
```

### 13.3 Post-check

FastClaw 输出不能直接成为最终用户答案。流程必须是：

```text
FastClaw draft
  -> AiphaBee evidence validator
  -> AiphaBee compliance classifier
  -> allowed / rewritten / blocked / human review
  -> final answer stream
```

FINRA 对生成式 AI 的监管提醒强调，使用 GenAI 和 LLM 不会消除既有监管义务；企业仍需考虑监督、记录、风控等义务。([FINRA][9])

## 14. FastClaw 风险与约束

### 14.1 License review

FastClaw Community License 允许把 FastClaw 作为自己 SaaS 产品的 backend 使用，但限制把 FastClaw 源码作为 FastClaw-as-a-Service 多租户平台卖给第三方，也限制修改/移除 FastClaw frontend branding。AiphaBee 如果只把 FastClaw 作为内部 API backend，且用户不直接接触 FastClaw UI，方向上更匹配 permitted use，但上线前仍需做 license review。([GitHub][10])

### 14.2 Per-user credential 风险

FastClaw 有 open issue 指出 shared agent 的 skill credentials 可能是 agent scope，而不是 per-chatter scope；报告者观察到 shared agent 场景下 user B 可能使用 owner A 注入的 token。投研场景不能把券商 token、交易 token、个人数据凭证直接放进 FastClaw skill env。([GitHub][11])

PRD 约束：FastClaw 只能拿 job-scoped token 调 AiphaBee Tool Gateway。所有真实用户凭证、券商连接、portfolio 原始数据留在 AiphaBee。

### 14.3 部署镜像风险

FastClaw 有 open issue 指出文档中的 container images 无法直接 pull，GHCR package private、docker-compose image 不存在。上线不能依赖 floating image 或官方 quickstart，必须 pin commit、自己 build、推送到私有 registry。([GitHub][12])

### 14.4 数据删除风险

FastClaw 有 open issue 指出 `DELETE /api/users/{id}` 删除用户失败。AiphaBee 必须拥有最终数据生命周期控制；FastClaw 删除可以作为 best-effort 子流程，但不能作为合规删除的唯一机制。([GitHub][13])

## 15. 可靠性设计

### 15.1 FastClaw circuit breaker

AiphaBee API 维护 runner health：

```text
healthy
degraded
unavailable
maintenance
```

当 FastClaw 连续失败超过阈值：

```text
停止新建 research run
已有 run 标记 retryable
前端显示降级提示
Generic Agent 继续可用
告警通知工程/运维
```

### 15.2 Timeout

Generic Agent：

```text
first-token timeout: 5s
total timeout: 30s
tool timeout: 3-8s
```

Research Agent：

```text
runner connect timeout: 5s
first progress timeout: 10s
soft run timeout: 180s
hard run timeout: 600s
```

超过 soft timeout 时，用户看到“研究仍在继续，可稍后查看”。超过 hard timeout，run 失败并可重试。

### 15.3 幂等

创建 run 使用 `request_id`。

FastClaw callback / stream event 使用：

```text
run_id
event_index
runner_event_id
```

重复事件被 API 去重。

### 15.4 事故隔离验收

必须通过以下测试：

```text
kill FastClaw process
Generic Agent 仍可用
登录/订阅/API 主功能仍可用
Premium run 不返回 500 风暴
API p95 不明显劣化
告警触发
用户看到可理解降级文案
```

## 21. 关键产品决策

第一，**Layer 1 不是弱化版投顾，而是通用问答层**。它的价值是快、稳、便宜、可免费使用。

第二，**Layer 2 不是独立 API，而是付费 Runner**。它的价值是深度研究、记忆、sandbox、长任务和用户专属体验。

第三，**AiphaBee API 永远是唯一 authority**。鉴权、订阅、合规、证据、审计、计费、数据生命周期都不能漂移到 FastClaw。

第四，**MVP 对外叫 AI 投研助手，不叫 AI 投顾**。等牌照、协议、适当性、人审、留痕、冲突披露准备好，再打开更强的 advisory mode。

第五，**Runner 可以换，用户关系不能换**。未来 FastClaw 如果不稳定，可以替换成自研 Runner、Vercel WorkflowAgent、Temporal worker、Cloudflare Workflows 或其他 agent harness；前端和 AiphaBee public API 不应变化。
