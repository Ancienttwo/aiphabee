可以。这个定义我会正式收敛成一个可落地方案：

> **用户发起临时公开 OHLCV 获取 → 可把 bounded OHLCV 发给 LLM，也可走确定性接口算信号 → LLM 解释 → 展示给用户。**
> 数据等级叫 **public_observation_signal**，不是 licensed market data，也不是 authoritative evidence。

重点不是「OHLCV 不能返回给 LLM」，而是：**不要把未授权的公开 OHLCV 产品化成平台默认、批量、后台、持久化的数据源。**

允许 bounded raw OHLCV 进入 LLM 的 ephemeral context，也允许展示给用户，但必须同时满足六个约束：`no-persistence`、`bounded-scope`、`user-initiated`、`no-background`、`no-batch`、`no-authorized-claim`。

# 1. 方案名称

建议内部命名：

```text
Ephemeral Public OHLCV Skill
```

用户可见命名：

```text
临时公开行情分析
```

数据等级：

```text
public_observation_signal
```

不是：

```text
authorized_market_data
licensed_evidence
official_price_feed
```

这套方案的产品定位是：

```text
用户显式发起一次公开行情读取，
系统短时间内临时处理，
输出技术观察信号，
不长期保存原始 K 线，
不作为授权行情证据，
不做后台自动刷新。
```

# 2. 核心链路

```text
用户发起技术分析请求
  ↓
Agent 判断是否需要临时 OHLCV
  ↓
AiphaBee Tool Gateway 调用 Ephemeral OHLCV Skill
  ↓
stock-sdk / public fetch 获取 bounded OHLCV（单标的、有限 lookback）
  ↓
user-private ephemeral cache，session-scoped TTL
  ↓
normalizeEphemeralBars()（去重/校验/补齐，保证数据质量）
  ↓
可把 bounded OHLCV 发给 LLM 的 ephemeral context
  ↓
也可走 computeIndicators() / computeSignals() 确定性接口算信号
  ↓
LLM 基于 OHLCV + 信号摘要生成解释
  ↓
展示给用户（信号卡片 + 可查看 OHLCV），标注 public_observation_signal
  ↓
六约束护栏：no-persistence / bounded / user-initiated / no-background / no-batch / no-authorized-claim
```

关键点：**OHLCV 可以进 LLM 的 ephemeral context，也可以展示给用户。**
护栏不是「不给 LLM」，而是六约束：OHLCV 只在当次会话内 bounded 使用，不落平台持久层、不批量、不后台、不冒充授权行情源。bounded bars 先经 normalizeEphemeralBars 校验以保证质量。FastClaw 不能自己 fetch，只能通过 Tool Gateway 拿结果。

# 4. 产品边界

## 4.1 允许

```text
用户问：“帮我临时分析一下 NVDA 日线技术面”
用户问：“基于公开行情，看看 00700 最近趋势”
用户问：“拉一下这只股票最近 200 根 K 线，算 RSI/MACD 信号”
用户在本会话内继续追问：“刚才那个 RSI 是什么意思？”
```

系统可以：

```text
临时获取 bounded OHLCV
session-scoped 私有缓存
把 bounded OHLCV 发给 LLM ephemeral context
计算指标
生成技术观察
展示数据来源、获取时间、延迟说明
展示信号摘要
展示 bounded OHLCV（表格 / 图表）
```

## 4.2 不允许

```text
后台自动刷新 watchlist                         # no-background
全市场扫描                                      # bounded / no-batch
批量拉几千只股票                                # no-batch
定时生成日报/周报                               # no-background
长期持久化 raw OHLCV 到平台层                   # no-persistence
把 raw OHLCV 做成常驻 API / 批量 export 数据源  # no-persistence / no-batch
把结果标成官方授权行情                          # no-authorized-claim
写入 shared market_bars                         # no-persistence
写入正式 evidence store                         # no-persistence
跨用户复用缓存                                  # no-persistence / bounded
FastClaw/E2B 直接访问行情源                      # 架构护栏
```

## 4.3 可延后

```text
授权行情源
可复现正式技术分析报告
长期历史行情库
自动 watchlist 信号
用户订阅型预警
组合级批量技术面扫描
```

这些以后有正式数据授权后再打开。

# 5. 数据分类

建议把数据分成三类。

| 数据类型                         | 来源                  | 是否可客户可见 |    是否存 raw |  是否进 evidence |
| ---------------------------- | ------------------- | ------: | ---------: | ------------: |
| `public_observation_signal`  | 用户临时 fetch 公开 OHLCV |      可以 | 短 TTL 私有缓存 | 不进正式 evidence |
| `authorized_market_evidence` | 授权数据源               |      可以 |  按 license |            可以 |
| `user_uploaded_data`         | 用户上传 CSV/图表         |      可以 |      按用户授权 |     可以，但标 BYO |

这次方案属于第一类。

# 6. Raw OHLCV 存储策略

## 6.1 默认策略

```text
raw OHLCV 不写 DB（平台持久层）
raw OHLCV 不写 shared market_bars
raw OHLCV 不写 evidence_lineage
raw OHLCV 不跨用户 cache
raw OHLCV 不做成常驻 export API / 批量数据源
raw OHLCV 可进 LLM ephemeral context（当次会话内 bounded 使用）
```

## 6.2 短缓存策略

允许短 TTL 私有缓存：

```text
scope: tenant_id + user_id + session_id + symbol + timeframe + lookback + provider_version
ttl_default: 24 hours
ttl_max: 24 hours
visibility: same user, same session
purpose: follow-up calculation consistency
```

缓存 key 示例：

```text
ephemeral_ohlcv:{tenant_id}:{user_id}:{session_id}:{market}:{symbol}:{timeframe}:{lookback}:{adjust}:{provider_version}
```

缓存 value 可以是加密后的 bars JSON，但必须：

```text
设置 TTL
不进入备份型持久库
不跨用户复用
不用于后台任务
不作为平台数据资产
```

如果你想更保守，第一版可以完全不缓存 raw bars（每次 fetch 后即时 normalize 再用），只缓存 signal summary。

## 6.3 三个独立存储层

「不存 OHLCV」必须说精确。它只约束 **AiphaBee 平台持久层**，管不到另外两层。这是工程事实，不是版权判断。

```text
层 1 · AiphaBee 平台持久层（market_bars / evidence / 备份库）
  → 不写。这是「不存 OHLCV」真正指的东西。

层 2 · Chat transcript（聊天记录）
  → 独立层。一旦 raw rows 出现在回答里、且聊天历史会被保存，
    raw OHLCV 就已经存在于 transcript 里。
  → 由 raw_to_chat_transcript 单独决定，不受层 1 约束。

层 3 · 第三方 model provider（OpenAI / 其他）
  → 独立层，AiphaBee 控制不了。
  → OpenAI API 默认不用于训练，但 abuse monitoring logs 默认最多保留 30 天；
    Zero Data Retention / Modified Abuse Monitoring 需额外申请批准。
  → 参考：openai.com/policies/row-terms-of-use、developers.openai.com/api/docs/guides/your-data
```

所以承诺口径必须对齐层 1，别说成「完全不存」：

```text
AiphaBee 不写 DB          ≠ 第三方 provider 不处理 / 不保留
AiphaBee 不存 market_bars ≠ 聊天记录里没有 raw rows
用户发起 fetch            ≠ 可以宣传成授权行情源
```

针对层 2，产品上提供两种 transcript 模式：

```text
模式 A：显示 raw rows，允许进入聊天历史
  文案：raw OHLCV 不写正式行情库，但可能存在于本次会话记录。

模式 B：临时查看 raw rows，不写入持久聊天历史
  文案：raw table 只在前端 session / 临时 artifact 展示，过期清除。
```

要严格对外说「不存 raw OHLCV」，就走模式 B，raw table 不落长期 transcript；
不介意 transcript 存，走模式 A，但文案不能说「完全不存」。

# 7. 持久化什么

可以持久化 run 级元数据和信号摘要。

```json
{
  "run_id": "run_...",
  "data_classification": "public_observation_signal",
  "symbol": "NVDA",
  "market": "US",
  "timeframe": "1d",
  "lookback_bars": 200,
  "provider": "stock_sdk_public",
  "retrieved_at": "2026-07-03T21:32:00Z",
  "raw_bars_returned": true,
  "raw_bars_persisted": false,
  "ephemeral_cache_ttl_seconds": 86400,
  "input_hash": "sha256:...",
  "signal_summary": {
    "trend": "uptrend",
    "momentum": "positive_but_extended",
    "volatility": "elevated",
    "volume_confirmation": "mixed"
  }
}
```

不要持久化：

```text
完整 OHLCV rows
完整 provider response
可重建原始行情库的数据结构
```

可以持久化：

```text
symbol
timeframe
lookback
provider id
retrieved_at
bars_count
data_quality summary
indicator summary
signal summary
answer hash
```

> 注意：本节讲的是 AiphaBee 平台持久层。**chat transcript 是独立存储层**——回答里若展示 raw rows，它会进 transcript，由 6.3 的 `raw_to_chat_transcript` 决定，不受本节「不持久化完整 OHLCV rows」约束。

# 8. Tool 设计

## 8.1 不暴露 raw fetch tool 给模型

不要让模型直接调用：

```text
fetch_public_ohlcv_raw
```

而是暴露一个处理后的 tool：

```text
analyze_public_technical_signal
```

这个 tool 内部做：

```text
fetch bounded OHLCV
normalize（校验/去重/补齐）
compute indicators
compute signals
return summary + bounded OHLCV bars
```

模型拿到 signal summary，并可在 detail_level=with_bars 时附带 bounded OHLCV bars。

# 9. 数据处理接口

建议在 `@aiphabee/market-data` 里加三个 deterministic functions。

```ts
normalizeEphemeralBars()
computeTechnicalIndicators()
computeTechnicalSignals()
```

## 9.1 normalizeEphemeralBars

职责：

```text
统一字段
统一时间戳
排序
去重
校验 OHLC 合法性
校验 volume
处理时区
识别最新未完成 bar
识别缺失 bar
限制 bars 数量
```

校验规则：

```text
high >= max(open, close)
low <= min(open, close)
volume >= 0
timestamp 单调递增
bars_count >= minimum required
timeframe 合法
lookback <= max allowed
```

异常结果：

```text
INSUFFICIENT_BARS
INVALID_OHLC_RELATION
DUPLICATE_TIMESTAMP
STALE_DATA
INCOMPLETE_LATEST_BAR
PROVIDER_UNAVAILABLE
```

---

## 9.2 computeTechnicalIndicators

第一版指标：

```text
MA 5 / 20 / 60
EMA 12 / 26
MACD 12 / 26 / 9
RSI 14
BOLL 20 / 2
ATR 14
Volume MA 20
OBV
```

第二版再加：

```text
KDJ
DMI / ADX
CCI
VWAP
MFI
NATR
```

注意：指标计算可以用 `stock-sdk/indicators`，但输入必须是 normalize 后的 bars。

---

## 9.3 computeTechnicalSignals

不要直接输出“买入/卖出”。输出观察型信号。

```ts
type TechnicalSignal =
  | 'trend_up'
  | 'trend_down'
  | 'trend_sideways'
  | 'momentum_positive'
  | 'momentum_extended'
  | 'momentum_diverging'
  | 'volatility_elevated'
  | 'volume_confirming'
  | 'volume_diverging'
  | 'near_recent_range_high'
  | 'near_recent_range_low'
  | 'breakout_observation'
  | 'pullback_observation'
  | 'insufficient_data';
```

不要输出：

```text
buy_signal
sell_signal
stop_loss
target_price
position_size
```

可以输出：

```text
短期趋势偏强
动量处于扩张状态
波动率高于近期均值
成交量确认不足
接近近期区间上沿
近期回撤风险上升
```

# 10. Agent 回答模板

最终回答建议固定格式。

```text
数据口径
- 本分析基于你本次发起获取的公开行情数据临时计算。
- 数据不是 AiphaBee 授权行情源，可能存在延迟或不完整。
- 原始 OHLCV 可在本次会话内展示与引用，但不作为常驻数据源批量导出。

信号摘要
- 趋势：
- 动量：
- 波动：
- 成交量：

关键观察
1. ...
2. ...
3. ...

风险提示
- ...

可继续追问
- 我可以进一步解释 RSI/MACD/BOLL 的含义。
- 也可以结合你上传的图表做视觉技术分析。

免责声明
- 以上仅为公开来源临时技术观察，不构成投资建议。
```

示例输出：

```text
根据你本次发起获取的公开行情数据，我临时计算到 NVDA 的短期趋势仍偏强，
RSI(14) 接近高位区间，MACD 仍位于零轴上方，但动能扩张速度有所放缓。
成交量信号偏混合，说明上涨趋势仍有延续迹象，但短期回撤风险也在上升。

该结果属于 public_observation_signal，不是 AiphaBee 授权行情验证，
也不构成买入、卖出或持有建议。
```

## 10.1 展示 raw OHLCV 时

用户明确要看 raw K 线（例如「展示最近 30 根」）时可以展示，但表格前必须带口径说明：

```text
以下 OHLCV 是根据你本次请求临时获取的公开行情数据。
它不是 AiphaBee 授权行情源，也不会写入 AiphaBee 正式行情库。
数据可能延迟或不完整，仅用于本次技术观察。
```

然后展示 bounded 表格：

```text
Date        Open     High     Low      Close    Volume
2026-07-01  123.10   126.40   121.90   125.70   123456789
...
```

信号输出接在表格后：

```text
基于上述数据，RSI(14) 处于高位区间，MACD 仍在零轴上方但动能放缓。
这属于 public observation，不构成买入、卖出或持有建议。
```

默认仍是「先给摘要 + 可展开 raw data」；raw table 是否落 transcript 见 6.3 模式 A/B。

# 12. 权限与限流

## 12.1 Entitlement

建议只给 Research / Pro 开。

```text
Free:
  不开放，或每日极低额度

Pro:
  开放临时公开技术分析

Premium:
  更高额度，可结合图表上传 / 组合上下文

  使用授权数据源，不走 public_observation 默认路径
```

## 12.2 Rate limits

第一版建议：

```text
max_symbols_per_run: 1

max_bars_to_llm: 500
max_bars_to_display: 500
default_bars: 250
max_timeframes_per_run: 2
```

```text

无限分页

```

后续如果要做 watchlist 技术面，就必须进入授权数据源路径。

```ts
  // 允许
  raw_to_llm_context: true,
  raw_to_user_display: true,

  // 禁止 / 默认关闭
  raw_to_market_database: false,
  raw_to_shared_cache: false,
  background_refresh: false,
  batch_scan: false,
  provider_as_authorized_feed: false,

  // transcript 层可配置（见 6.3 模式 A/B）

    max_symbols_per_run: 1,
    max_bars_to_llm: 500,
    max_bars_to_display: 500,
```

Generic Agent 禁止调用：

```text

```


# 14. FastClaw / E2B 边界

FastClaw 不能内置这个 Skill。

正确做法：

```text
FastClaw
  ↓
AiphaBee Tool Gateway
  ↓
analyze_public_technical_signal
```

FastClaw 不允许：

```text
直接 import stock-sdk
直接 fetch public market data
直接保存 OHLCV 到 workspace
直接把 raw bars 放进 memory
直接把 raw bars 写进 files
```

E2B sandbox 里也不要放 raw OHLCV，除非只是当前 tool invocation 的内存态处理，并且不落盘。

更稳的做法是：**OHLCV fetch + indicator computation 全在 AiphaBee Tool Gateway 内完成，FastClaw 只拿 signal summary。**

# 17. 安全与滥用控制

## 17.1 防止批量化

拦截：

```text
分析整个美股市场
扫描所有 A 股
找出今天 MACD 金叉股票
帮我跑全市场 RSI 小于 30
每小时自动刷新我的 watchlist
```

返回：

```text
当前临时公开行情 Skill 只支持用户发起的单标的、有限 lookback 技术观察。
全市场扫描和后台刷新需要授权数据源支持。
```

## 17.2 控制 OHLCV 呈现口径

bounded OHLCV 可进 LLM、可展示给用户。post-check 不再拦截 OHLCV 本身，而是确保：

```text
每处 OHLCV 展示都带 public_observation 标注 + 获取时间 + 延迟说明
不冒充授权 / verified 行情
不把当次结果扩成批量 / 全市场 / 后台 export
```

只有「无标注地把 OHLCV 当授权行情」或「批量 / 后台导出」才 rewrite 或 block。

## 17.3 防止 prompt injection

模型不能决定：

```text
provider URL
无限 lookback
批量 symbol
缓存 TTL
background job
```

这些全部由 deterministic policy 控制。

# 22. 最终建议

我建议你正式采用这个模式：

```text
user-initiated ephemeral OHLCV
  → short-lived private cache
  → deterministic indicators
  → public_observation_signal
  → research-only Agent explanation
```

同时加一句铁律：

```text
它是临时公开观察，不是授权行情数据源。
```

这样你既能把技术分析 Agent 做起来，也不会把自己锁死在“必须一开始就买完整行情授权”的路径上。后面等产品验证后，再把底层 provider 从 `stock-sdk_public_ephemeral` 平滑切到正式授权数据源即可。
